# Cadence — аудит перенесення AI-native Development Kit
Дата: 07.10.2026.
Перевірений репозиторій: uwavecom/Cadence, main, commit `3d4da3049aa178d6499bd3a3077f6ccf4a1e85ff`.

## Висновок
Cadence має достатню основу для поступового перенесення правил Kit. Пріоритет — коректність вхідних даних, часу, циклів та атомарних записів, а не додавання всіх шарів чи ролей з еталонного прикладу.

Це статичний аудит коду GitHub і три локальні відтворення поведінки JavaScript. Повний застосунок, SQLite інтеграцію, npm test і build у цьому аудиті не запускали. Локальні незбережені зміни користувача не перевірені.

## Що вже є
- Next.js 14.2.15, React 18, TypeScript strict, Vitest.
- SQLite через better-sqlite3; параметризовані SQL-запити.
- Чиста функція nextOccurrence у src/core/recurrence.ts.
- Два тести щомісячного повторення, включно з 31 січня → 28 лютого.
- Завершення задачі, подія та наступне повторення об'єднані транзакцією.
- Унікальні ключі процесу/циклу/етапу.
- README застарів: SQLite уже реалізований.

## Локальні відтворення
1. Number("invalid") → NaN; вираз !(day < 1 || day > 31) → true.
2. new Date("invalid").toISOString() → RangeError.
3. Введення 2026-10-25T18:00: у TZ=UTC → 18:00Z; у TZ=Europe/Kyiv → 16:00Z.
Це відтворення окремих виразів, а не повні тести Server Actions.

## Профіль Cadence
- core: моделі, валідація, правила дат, повторень та переходів; без Next.js і SQLite.
- application: use cases для create/complete/ensure-cycle; оркестрація.
- db: SQLite та транзакції, мапери, зберігання.
- app/actions: перевірка зовнішнього input, виклик use case, revalidation.
- Server Components можуть викликати read-only application queries.
- components: UI; клієнтський граф не імпортує db, Node-only SDK чи server-only implementation.
- Не потрібен окремий generic repository framework для кожної маленької операції.
- better-sqlite3 лише в db; core не імпортує app, application або db.
- Авторизація: особистий локальний режим має бути зафіксований як deployment constraint. Код не має identity/permission checks; це стає блокером перед віддаленим або багатокористувацьким доступом. У цьому аудиті доступність у мережі не перевірена.

3. Транзакції та завершення: task+event, цикл+етапи, повторне завершення, відкат при помилці, конкурентні операції.

5. Підключити verify/CI та правила імпортів під реальний стек Cadence; перевірити правила навмисним порушенням.
